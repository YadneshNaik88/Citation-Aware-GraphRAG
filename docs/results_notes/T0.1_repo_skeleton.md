# Task Results Note: T0.1 Repository Skeleton

## 1. Task Restatement and Acceptance Criteria
- **Task:** Create repository skeleton strictly adhering to `docs/ARCHITECTURE.md` Section 5.
- **Scope:**
  - Create packages `src/{data,kg,embed,topics,forecast,rag,verify,gaps,app,common}` with `__init__.py`.
  - Create canonical folders `configs/`, `tests/`, `scripts/`, `docs/results_notes/`, `docs/annotation/`, and `.agents/rules/`.
  - Maintain canonical documentation solely inside `docs/` (`docs/ARCHITECTURE.md`, `docs/PROTOCOL.md`, `docs/PHASE_0_PROMPTS.md`), with `AGENTS.md` at root.
  - Pin Python minor version to `3.13` after wheel verification and document in `docs/ENVIRONMENT_NOTES.md` and `.python-version`.
  - Create `requirements.txt` with exact `==` pins for direct dependencies (`pytest`, `ruff`, `pyyaml`) and `requirements-lock.txt` generated by `pip freeze` from a clean virtual environment.
  - Implement `Makefile` with targets: `setup`, `test`, `lint`, `leakage`, `lock`, `env-report`.
  - Implement `scripts/env_report.py` and test `tests/test_env_report.py` verifying hardware-agnostic execution.
  - Implement `tests/test_repo_layout.py` asserting canonical directories, forbidding competing folders (`config/`, `source/`, `utils/`, `data_raw/`), and preventing duplicate root copies of documentation.
  - Configure `.env.example`, `.gitignore`, `pyproject.toml`, `CHANGELOG.md`, `OPEN_QUESTIONS.md`, and `.github/workflows/ci.yml`.
- **Acceptance Criteria:**
  - `make setup && make test && make lint` pass locally and in CI.
  - `pip freeze` inside `.venv` matches `requirements-lock.txt`.
  - Layout tests pass and fail if a `config/` folder or root doc duplicate is added.
  - `env_report.py` output is saved under `runs/env_report.json`.
  - Clean clone verification passes on a fresh clone.
  - PR opened against `main` on GitHub with green CI.

## 3. Real Inputs & Package Compatibility Inspection
Python 3.13 (specifically 3.13.14 on Windows 10 version 10.0.19045 AMD64) was selected and verified. Prebuilt wheels and imports were inspected:
- `torch`: 2.13.0+cpu verified via live import.
- `faiss-cpu`: 1.15.1 verified via live import.
- `duckdb`: 2.0.0 (uses CPython stable ABI `abi3`, compatible with 3.13).
- `polars`: 2.1.0 (uses CPython stable ABI `abi3`, compatible with 3.13).
- `transformers`: 4.57.6 (universal wheel).
- `adapters`: 1.3.0 (universal wheel).

### Downstream Planning:
1. Full end-to-end runtime compatibility of the combined heavy stack (`torch` + `transformers` + `adapters` + `faiss-cpu`) remains to be established during the actual installation and benchmark in T0.3.
2. For PyTorch packaging across platforms, the proposed strategy is to keep platform-specific PyTorch builds outside the shared cross-platform lockfile, using separately pinned environment files (e.g. `requirements-torch-cpu.txt`, `requirements-torch-cuda.txt`), pending team approval.

Details recorded in `docs/ENVIRONMENT_NOTES.md`.
